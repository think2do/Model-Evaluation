# 模型回答裁判器｜需求说明

## 1. 要做什么

做一个仅在本地使用的轻量网页，用 DeepSeek V4 Flash 对多个已提供的模型回答进行评测。

用户输入原始问题、对应的评分标准，以及一份或多份“模型名称 + 模型回答”。网页将评分标准与每份回答提交给裁判模型，展示逐项判定、分数和排序结果。

评分标准由用户事先准备并粘贴；网页不生成题目或评分标准。

## 2. 给谁用

面向需要手动比较多个模型回答质量的个人用户。用户已经拥有待评问题、可执行的评分标准，以及来自不同模型或不同提示词版本的回答。

第一版假定用户仅在自己的本地浏览器中使用网页，并接受 API Key 直接写入前端代码这一简化方式。

## 3. 核心场景

1. 用户粘贴“原始问题”和“评分标准”。
2. 用户添加多个待评回答；每份回答包含模型名称和回答正文。
3. 用户点击“开始评测”，当有多个回答结果时同时并发判断。
4. 网页调用 DeepSeek V4 Flash，依据用户提供的评分标准，分别裁判每份回答。
5. 网页展示每份回答的：
   - 红线检查结果；
   - 原始分、最终分、得分率；
   - 每个评分项（如 C01、C02）的 0/1 结果、判定理由和直接证据；
   - 按最终分排序的结果；同分并列。
6. 如果裁判模型的返回无法被结构化读取，网页保留并显示原始返回文本，并提示该次结果需要重新评测或人工查看；不得自行补全、修正或伪造分数。

## 4. 明确不做什么

- 不生成评测题目、评分标准或参考答案。
- 不调用其他模型自动生成待评回答；回答仅由用户手动粘贴。
- 不提供登录、账号、多用户协作、数据库、云端保存或历史记录。
- 不提供题库、批量导入导出、数据分析报表或自动化评测任务。
- 不设置固定的通用评测维度；评分项完全以用户粘贴的评分标准为准。
- 不进行多轮追问、自动纠错或自动修复裁判模型的不规范输出。
- 不设置后端、代理服务或环境变量配置；第一版仅作为本地前端网页使用。

## 5. 完成边界

当用户能在本地页面中粘贴题目、标准和多份回答，发起一次裁判请求，并查看逐项结果与按分数排序的比较结果时，第一版即完成。
