# 模型回答裁判器｜技术选型与架构说明

本文以 [需求说明.md](./需求说明.md) 的第一版范围为准：仅做本地使用的裁判器。

## 1. 技术选型

| 范围 | 选择 | 原因 |
| --- | --- | --- |
| 页面 | HTML5 | 页面只有单一工作台，无需路由、服务端渲染或复杂工程化。 |
| 样式 | 原生 CSS | 可完成表单、卡片、评分表格、状态提示等界面；不引入组件库与构建步骤。 |
| 交互与状态 | 原生 JavaScript（ES Modules） | 足以处理动态添加回答、调用 API、解析结果、排序和异常显示。 |
| 前端框架 | 不使用 React/Vue 等框架 | 第一版状态少、页面少；零依赖更符合“本地、简单”的目标。以后界面复杂时再迁移。 |
| 第三方库 | 不使用 | 不需要图表、日期处理、请求封装或 Markdown 编辑能力。浏览器原生 `fetch` 即可请求 API。 |
| 模型 API | DeepSeek Chat Completions API | 官方文档显示其 OpenAI 兼容接口基地址为 `https://api.deepseek.com`，模型名为 `deepseek-v4-flash`。 |
| 结构化返回 | DeepSeek JSON Output：`response_format: { type: "json_object" }` | 官方支持 JSON 输出，适合前端稳定读取动态数量的 C01、C02……评分项。提示词仍须明确要求 JSON，且页面必须处理空内容或解析失败。 |
| 数据存储 | 不使用数据库，也不默认持久化 | 用户要求本地轻量工具；刷新页面后本次输入与结果消失。 |

### 已确认的 API 事实

- DeepSeek 的 Chat Completions 端点为 `POST https://api.deepseek.com/chat/completions`，可使用模型 `deepseek-v4-flash`。
- DeepSeek 支持 JSON Output；启用时需请求 `response_format: { "type": "json_object" }`，并在提示词中明确要求 JSON。
- 官方文档也说明 JSON Output 偶尔可能返回空内容。因此页面需要把“空内容”和“非合法 JSON”作为可见失败状态处理，不能把它们当成有效评测。

来源：[DeepSeek API 首次调用说明](https://api-docs.deepseek.com/guides/function_calling/)、[DeepSeek JSON Output 指南](https://api-docs.deepseek.com/guides/json_mode/)。以上于 2026-07-29 查阅。

## 2. 架构与模块划分

项目是纯静态前端，建议仅包含三个源文件：

```text
index.html       页面结构
styles.css       页面样式
app.js           输入状态、请求、结果校验和渲染
```

文字架构图：

```text
用户
  │ 输入：原始问题、评分标准、多个模型回答
  ▼
输入表单与内存状态（app.js）
  │ 点击“开始评测”
  ▼
裁判请求构造器
  │ 为每份回答组合：裁判指令 + 原始问题 + 评分标准 + 当前回答
  ▼
浏览器 fetch
  │ HTTPS 请求；Authorization Bearer 使用前端配置的 API Key
  ▼
DeepSeek Chat Completions（deepseek-v4-flash）
  │ 返回 JSON 文本
  ▼
结果校验与转换器
  ├─ 合法、字段齐全：转为页面结果数据
  └─ 空内容、非 JSON 或关键字段缺失：保留原始文本，标记“无法结构化展示”
  ▼
结果渲染器
  ├─ 按最终分排序（同分并列）
  └─ 展示总分、红线与 C01…Cn 的理由、证据
```

### 模块职责

| 模块 | 职责 |
| --- | --- |
| 输入表单 | 收集问题、标准、模型名和回答；支持添加与删除回答。 |
| 输入校验 | 阻止提交空问题、空标准、空模型名或空回答；不判断评分标准本身是否高质量。 |
| 裁判请求构造器 | 每次只把一份待评回答连同同一题目和标准发送给裁判模型，防止不同回答互相影响判定。 |
| API 客户端 | 用 `fetch` 调用 DeepSeek；处理网络错误、HTTP 错误、超时或模型空返回。 |
| 结果校验器 | 校验返回是否为 JSON，评分项编号是否存在、得分是否仅为 0 或 1、汇总字段是否可读取。不会改写模型结论。 |
| 排序器 | 仅依据已读取的“最终分”排序；同分并列。它不要求模型额外给出主观排名。 |
| 结果视图 | 展示成功结果；发生解析错误时展示原始返回和失败提示。 |

## 3. 数据流转

1. 用户在页面填写数据，JavaScript 将其保存在浏览器当前页面的内存中。
2. 点击评测后，前端为每个模型回答单独构造请求；题目和评分标准在各请求中保持相同。
3. 请求携带 API Key 直接从浏览器发往 DeepSeek。此为已确认的第一版取舍：仅限本地使用，不能部署或分享页面。
4. DeepSeek 返回的 JSON 文本先被解析，再经前端的最小字段校验。
5. 校验通过的结果进入结果列表，由前端依最终分排序后渲染；失败结果不参与排序，显示其原始返回文本。
6. 不写入本地存储、数据库或网络服务；刷新或关闭页面即清除当次数据。

## 4. 数据结构草图

第一版没有数据表或数据库。以下是 JavaScript 运行时的数据形状，用于约束前端读写，不代表需要保存为文件。

```js
// 用户在表单中提供的本次评测
const evaluationInput = {
  question: "原始问题全文",
  rubric: "评分标准全文",
  candidates: [
    {
      id: "浏览器生成的临时 ID",
      modelName: "模型 A",
      answer: "待评回答全文"
    }
  ]
};

// 前端期望从裁判模型读取的一份结果
const judgeResult = {
  modelName: "模型 A",
  redline: {
    triggered: false,
    details: "无红线规则或未触发"
  },
  rawScore: 12,
  finalScore: 12,
  scoreRate: 92,
  items: [
    {
      id: "C01",
      score: 1,
      reason: "判定理由",
      evidence: "回答中的直接证据；没有则为 未提供明确证据"
    }
  ],
  verification: "各评分项得分之和＝原始分",
  rawResponse: "DeepSeek 原始返回文本"
};
```

`items` 是动态列表：它的数量和编号来自用户粘贴的评分标准，不由网页预设。前端只负责显示经过验证的项目；不认识、缺失或矛盾的字段会被作为结构化失败处理。

## 5. 有意保留的限制

- API Key 位于前端代码中，任何能读取网页源码的人都可能获得它；因此只能本地使用，不应部署到公网或分享页面文件。
- 无持久化意味着没有历史记录，也不能在刷新后恢复。
- 结构化输出能降低解析失败率，但不能保证裁判结论正确；“直接证据”和原始返回会始终保留，供用户复核。
