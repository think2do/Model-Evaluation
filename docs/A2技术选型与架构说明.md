# A2 技术选型与架构说明

## 1. 文档目的

本文档根据 [A2 版本需求说明](需求文档.md) 给出技术实现建议，覆盖：

- 使用什么语言、框架和第三方库；
- 为什么选择这些技术；
- A2 的模块划分；
- 页面数据和 Excel 数据如何流转；
- 浏览器内存数据结构；
- Excel 单工作表结构草图；
- 导入校验、覆盖、时间更新和错误处理边界。

本文档是实现方案，不代表相关代码已经完成。当前主应用仍是根目录下的纯前端 HTML、CSS 和 JavaScript。

---

## 2. 当前项目约束

A2 应尽量保持现有项目的基本形态：

- 个人本地使用；
- 浏览器直接运行；
- 不增加后端；
- 不增加数据库；
- 不引入登录或多人协作；
- 不引入前端框架；
- 不要求 npm、打包器或构建命令；
- API Key 继续只从本地且被 Git 忽略的 `config.js` 读取；
- 页面数据只存在于浏览器内存；
- Excel 是网页全部数据的外部快照和恢复介质；
- 裁判结果继续采用严格解析，不自动修复矛盾数据。

A2 会明显增加状态管理、版本管理和文件处理逻辑，因此不建议继续把所有新增代码堆入现有 `app.js`。

---

## 3. 技术选型

### 3.1 总体选型

| 范围 | 选择 | 说明 |
| --- | --- | --- |
| 页面 | HTML5 | 延续现有静态页面，不引入路由和服务端渲染 |
| 样式 | 原生 CSS | 延续现有视觉体系和响应式布局 |
| 应用逻辑 | 原生 JavaScript | 与现有代码一致，不引入 React、Vue 等框架 |
| 脚本组织 | 多个经典脚本 + 单一全局命名空间 | 保持直接打开页面的兼容性，同时拆分模块 |
| Excel 读写 | SheetJS Community Edition | 在浏览器中读取和生成 `.xlsx` |
| 文件读取 | `<input type="file">` + `File.arrayBuffer()` | 由用户主动选择本地文件 |
| 文件下载 | SheetJS `writeFile` 或 `write` + Blob 下载 | 在浏览器中生成并下载 Excel |
| 数据存储 | 浏览器内存 | 不引入数据库、IndexedDB 或 `localStorage` |
| 外部评测 | 现有 DeepSeek Chat Completions API | 复用当前请求、解析和排名逻辑 |
| 时间格式 | ISO 8601 字符串 | 便于 Excel 保存、导入校验和跨环境解析 |
| 数据格式版本 | 显式格式版本字段 | 用于识别未来 Excel 结构变化 |
| 自动化测试 | Node.js 内置测试能力或轻量无构建测试脚本 | 优先测试纯数据模块，不改变运行时架构 |

### 3.2 为什么继续使用原生 JavaScript

当前应用已经使用原生 JavaScript 和 DOM API，A2 虽然增加了数据管理能力，但仍然是单页面、本地、个人使用的工具。

继续使用原生 JavaScript 的理由：

- 避免引入 npm 和构建流程；
- 不改变用户直接打开页面的使用方式；
- 可以复用当前请求构造、API 调用、严格解析和结果渲染逻辑；
- A2 的复杂度主要来自数据结构和文件校验，不依赖前端框架才能解决；
- 通过拆分纯函数模块，可以控制代码复杂度。

不建议在 A2 同时迁移 React、Vue、TypeScript 或打包器。框架迁移与 Excel 功能没有直接关系，会扩大改动范围和验证成本。

### 3.3 为什么暂不使用 ES Modules

ES Modules 更适合正式模块化，但当前项目允许直接打开本地 `index.html`。浏览器对 `file://` 页面加载模块脚本存在安全限制，不同浏览器表现也可能不同。

为维持现有运行方式，A2 建议继续使用经典脚本，并通过一个受控的全局命名空间暴露模块：

```js
window.ModelEvaluation = window.ModelEvaluation || {};
```

每个脚本只在该命名空间下暴露必要接口，避免新增大量无约束的全局变量。

如果未来明确要求通过本地静态服务器启动项目，可以再评估迁移 ES Modules。

### 3.4 Excel 库：SheetJS Community Edition

建议使用 SheetJS Community Edition 的浏览器独立版本。

选择理由：

- 官方文档明确支持在浏览器中读取 `ArrayBuffer`；
- 官方文档明确支持在浏览器中生成和下载 XLSX；
- 可以创建单工作表并把对象数组转换为表格；
- 不要求 React、Node.js 后端或数据库；
- 可以使用独立浏览器脚本，不要求打包器；
- Community Edition 使用 Apache License 2.0。

截至 2026-07-30，本次核验到的官方独立浏览器版本为 `0.20.3`。

实现时建议：

1. 固定具体版本，不使用自动变化的 latest 地址；
2. 将经过核验的脚本保存在项目本地，例如：

   ```text
   vendor/sheetjs/xlsx.full.min.js
   ```

3. 在项目的第三方软件说明中记录版本、来源和 Apache-2.0 归属信息；
4. 不依赖运行时 CDN，避免离线或网络异常导致导入导出不可用；
5. 下载第三方文件后核对官方来源和文件完整性，再提交到仓库。

实现阶段已将官方 SheetJS CE 0.20.3 浏览器文件固定到
`vendor/sheetjs/xlsx.full.min.js`，并保留 `LICENSE` 与 `NOTICE.md`。

### 3.5 为什么不选择手写 XLSX

`.xlsx` 实际是包含多个 XML 文件及关系描述的压缩包。手写解析和生成会涉及：

- ZIP 容器；
- 工作簿关系；
- 共享字符串；
- 单元格类型；
- 日期和数字格式；
- XML 转义；
- Office 兼容性。

自行实现的成本和出错风险明显高于使用成熟库，不适合作为 A2 的业务工作。

### 3.6 为什么不增加数据库或本地持久化

A2 已明确把 Excel 视为网页全部数据的外部存储。本版不要求刷新后自动恢复，也不要求云端保存。

因此当前数据仍只保存在内存中：

- 页面打开后创建或导入数据；
- 页面操作修改内存状态；
- 导出生成 Excel 快照；
- 刷新或关闭页面后，未导出的修改会丢失。

如果未来需要自动保存，再单独评估 `IndexedDB`。本版不引入 `localStorage`，因为完整回答和 JSON 结果可能较大，且简单键值存储不适合版本化数据。

## 5. 核心数据流

### 5.1 创建和编辑评测版本

```text
用户创建版本
  ↓
版本服务生成唯一 versionId
  ↓
写入版本名称、问题、评分标准和空记录列表
  ↓
设置 updatedAt
  ↓
保存到内存 Store
  ↓
UI 重新渲染
```

版本名称允许为空，版本 ID 必须存在且唯一。

版本公共信息或其任一记录发生有效修改时，更新该版本的 `updatedAt`。

### 5.2 单条评测

```text
选择一条记录
  ↓
读取所属版本的问题和评分标准
  ↓
读取记录的模型名和模型回答
  ↓
状态改为 evaluating
  ↓
调用 DeepSeek API
  ↓
严格解析结果
  ├─ 成功：覆盖 result，状态改为 success
  ├─ 请求失败：清除旧 result，写入最新错误
  └─ 解析失败：清除旧 result，写入错误和原始返回
  ↓
更新所属版本 updatedAt
  ↓
重新渲染
```

最新成功、请求失败或解析失败都覆盖旧状态。系统不保留旧结果。

### 5.3 批量评测

评测编排器支持四种入口：

1. 单条记录；
2. 当前版本下所有未评测记录；
3. 当前版本下全部记录重新评测；
4. 用户选择的多个版本。

四种入口最终都转换为统一的评测任务列表：

```js
[
  {
    versionId,
    recordId,
    question,
    rubric,
    modelName,
    answer
  }
]
```

每条任务继续独立请求。单条失败不应中断其他任务。

多版本同时评测的最大并发请求数为 99。超过上限的任务进入等待队列，直到已有请求完成或本次评测被用户终止。

评测任务尚未全部结束时，页面禁止导入和导出。用户可以手动终止本次评测；终止流程完成后，才恢复导入和导出入口。

### 5.4 Excel 导出

```text
用户点击导出
  ↓
读取 Store 中全部评测版本
  ↓
为每条记录生成一行
  ↓
版本公共字段在同版本各行中重复
  ↓
完整评测结果序列化为 JSON 字符串
  ↓
最终分、满分、得分率写入独立列
  ↓
SheetJS 创建单工作表 Workbook
  ↓
尝试生成并下载 XLSX
  ├─ 成功：为尚无 firstExportedAt 的版本写入时间
  └─ 失败：不写入 firstExportedAt，显示错误
```

导出时应先计算一个统一的本次导出时间。同一次导出涉及的所有首次导出版本使用相同时间值。

### 5.5 Excel 导入

```text
用户选择 .xlsx 文件
  ↓
File.arrayBuffer()
  ↓
SheetJS 读取 Workbook
  ↓
校验工作簿和单工作表结构
  ├─ 无法识别：停止，保留当前网页数据
  └─ 可以识别：继续逐行校验
                    ↓
              合法行 / 错误行分离
                    ↓
      按 versionId 聚合合法评测记录
                    ↓
      构造新的完整 Store 快照
                    ↓
      用新快照替换网页当前全部数据
                    ↓
      展示被跳过的行号和具体原因
```

导入行为不是追加：

- 当前网页数据不会与导入数据合并；
- 合法导入数据组成新的完整状态；
- 导入操作本身不改变 `firstExportedAt` 或 `updatedAt`；
- 错误行不进入新状态；
- 文件整体无法识别时不替换当前状态。

同一版本的公共字段在不同行中冲突时，跳过存在冲突的行，并在导入报告中列出行号、冲突字段和原因。不得跳过未冲突的合法行，也不得静默选择其中一个值。

如果文件结构有效但没有任何合法行，不替换网页当前状态，并返回全部错误行。

## 6. 浏览器内存数据结构草图

### 6.1 顶层应用状态

```js
{
  schemaVersion: "A2.1",
  activeVersionId: "version-uuid",
  versions: [
    // EvaluationVersion
  ],
  ui: {
    isImporting: false,
    isExporting: false,
    evaluatingRecordIds: [],
    lastImportReport: null
  }
}
```

`schemaVersion` 用于描述当前内存和 Excel 映射所使用的数据格式版本。正式值在实现时确定，不应把本文示例值直接当成已经发布的版本号。

### 6.2 评测版本

```js
{
  id: "version-uuid",
  name: "",
  question: "问题全文",
  rubric: "评分标准全文",
  firstExportedAt: null,
  updatedAt: "2026-07-30T10:20:30.000Z",
  records: [
    // EvaluationRecord
  ]
}
```

规则：

- `id` 必填且全局唯一；
- `name` 允许为空字符串；
- `question` 和 `rubric` 为版本公共字段；
- `firstExportedAt` 在首次成功导出前为 `null`；
- `updatedAt` 属于版本，不属于单条记录；
- 同一版本的所有 Excel 行重复保存相同的两个时间字段。

### 6.3 评测记录

```js
{
  id: "record-uuid",
  modelName: "模型名",
  answer: "模型回答全文",
  status: "unscored",
  result: null,
  error: null,
  rawResponse: null
}
```

建议内部状态值：

| 内部状态 | 含义 |
| --- | --- |
| `unscored` | 未评测 |
| `evaluating` | 评测中 |
| `success` | 评测成功 |
| `request-error` | 请求失败 |
| `parse-error` | 解析失败 |
| `terminated` | 已终止 |

导出文件不保存瞬时的 `evaluating` 状态。只要仍有评测任务运行或等待，导入和导出入口保持禁用。

### 6.4 成功结果

```js
{
  candidateId: "record-uuid",
  modelName: "模型名",
  redline: {
    triggered: false,
    details: "红线检查说明",
    appliedRule: null
  },
  items: [
    {
      id: "C01",
      score: 1,
      reason: "判定理由",
      evidence: "直接证据"
    }
  ],
  rawScore: 1,
  maxScore: 1,
  finalScore: 1,
  scoreRate: 100,
  verification: {
    itemScoreSum: 1,
    matchesRawScore: true,
    statement: "核对说明"
  }
}
```

该结构沿用当前严格解析器的核心结果形状。

### 6.5 错误信息

```js
{
  type: "request-error",
  message: "可读错误说明"
}
```

`type` 至少区分请求失败和解析失败。解析失败时，`rawResponse` 应尽可能保留裁判原始返回文本。

### 6.6 导入报告

```js
{
  fileName: "evaluation.xlsx",
  importedRowCount: 18,
  skippedRowCount: 2,
  errors: [
    {
      rowNumber: 6,
      code: "INVALID_RESULT_JSON",
      message: "完整评测结果 JSON 无法解析。"
    },
    {
      rowNumber: 11,
      code: "MISSING_MODEL_NAME",
      message: "模型名为空。"
    }
  ]
}
```

错误报告必须使用 Excel 中用户可见的实际行号，而不是从零开始的数组下标。

## 7. Excel 单工作表结构草图

### 7.1 一行一条评测记录

工作表建议命名为 `评测记录`。

每一行表示一条评测记录。同一评测版本有多条回答时，版本公共字段在多行中重复。

| 列 | 建议字段键 | 类型 | 规则 |
| --- | --- | --- | --- |
| 数据格式版本 | `schemaVersion` | 文本 | 必填，所有行一致 |
| 评测版本 ID | `versionId` | 文本 | 必填 |
| 评测版本名称 | `versionName` | 文本 | 允许为空 |
| 问题 | `question` | 长文本 | 必填 |
| 评分标准 | `rubric` | 长文本 | 必填 |
| 记录 ID | `recordId` | 文本 | 必填且全局唯一 |
| 模型名 | `modelName` | 文本 | 必填 |
| 模型回答 | `answer` | 长文本 | 必填 |
| 评测状态 | `status` | 枚举文本 | 必填 |
| 最终分 | `finalScore` | 整数 | 成功结果必填 |
| 满分 | `maxScore` | 正整数 | 成功结果必填 |
| 得分率 | `scoreRate` | 0–100 整数 | 成功结果必填 |
| 完整评测结果 JSON | `resultJson` | JSON 文本 | 成功结果必填 |
| 错误类型 | `errorType` | 文本 | 失败记录填写 |
| 错误信息 | `errorMessage` | 长文本 | 失败记录填写 |
| 原始裁判返回 | `rawResponse` | 长文本 | 有返回时填写 |
| 第一次导出时间 | `firstExportedAt` | ISO 8601 文本 | 同版本各行一致 |
| 最后更新时间 | `updatedAt` | ISO 8601 文本 | 必填，同版本各行一致 |

### 7.2 为什么完整结果使用 JSON 列

评分项数量由评分标准决定，不同版本可能包含不同数量的 C 项。

如果为每个评分项动态创建“得分、理由、证据”列：

- 列数量无法预先固定；
- 不同版本的列结构不一致；
- 导入校验复杂；
- 长理由和证据会让工作表极宽。

因此完整结果使用一个 JSON 列，常用的最终分、满分和得分率再单独冗余保存为摘要列。

导入成功结果时必须交叉校验：

- 独立 `finalScore` 等于 JSON 中的 `finalScore`；
- 独立 `maxScore` 等于 JSON 中的 `maxScore`；
- 独立 `scoreRate` 等于 JSON 中的 `scoreRate`；
- JSON 本身通过现有严格结果校验。

发现不一致时不得自行选择其中一个值，应把该行列为错误行。

### 7.3 状态与字段组合

| 状态 | `resultJson` | 分数摘要列 | 错误信息 |
| --- | --- | --- | --- |
| `unscored` | 空 | 空 | 空 |
| `success` | 必填 | 必填 | 空 |
| `request-error` | 空 | 空 | 必填 |
| `parse-error` | 空 | 空 | 必填 |
| `terminated` | 空 | 空 | 可填写终止说明 |

解析失败时，`rawResponse` 有内容则保留；没有收到可用原文时允许为空。

`evaluating` 是页面瞬时状态，不作为稳定导入状态。

`terminated` 是可以导入和导出的稳定状态，仅用于本次评测前没有旧成功结果、且任务被手动终止的记录。

已有成功结果的记录在重新评测时被终止，应保留原有 `success` 状态和完整旧结果，不写成 `terminated`，也不使用被终止的本次任务覆盖旧结果。

### 7.4 版本公共字段一致性

同一个 `versionId` 的所有行必须具有一致的：

- `schemaVersion`
- `versionName`
- `question`
- `rubric`
- `firstExportedAt`
- `updatedAt`

发生冲突时，导入校验器跳过存在冲突的行，并报告行号、冲突字段和具体原因。不能采用“第一行优先”或“最后一行优先”的隐式规则。

### 7.5 时间格式

建议以 UTC ISO 8601 字符串保存，例如：

```text
2026-07-30T10:20:30.000Z
```

理由：

- 不依赖 Excel 日期序列号；
- 不受本机区域日期格式影响；
- JavaScript 可以稳定解析；
- 字符串排序与时间顺序一致；
- 页面展示时可以转换为用户本地时区。

Excel 中保留原始 ISO 文本，不把时间字段导出成公式。

## 8. 导入校验设计

### 8.1 两级校验

导入采用两级校验：

#### 文件级校验

用于判断文件是否可以进入逐行导入：

- 文件能否读取；
- 是否为支持的工作簿；
- 是否存在且只使用目标工作表；
- 是否包含必要列；
- 列名是否可以唯一识别；
- 数据格式版本是否受支持。

文件级校验失败时：

- 停止导入；
- 不替换网页当前数据；
- 显示文件级错误。

#### 行级校验

文件级校验通过后，对每行检查：

- 必填字段；
- ID 格式与重复；
- 状态值；
- 数字类型和范围；
- 时间格式；
- 状态与结果字段组合；
- 结果 JSON 格式；
- 摘要分数与 JSON 一致性；
- 同版本公共字段一致性。

合法行进入新状态，错误行被跳过并加入导入报告。

### 8.2 JSON 安全

`resultJson` 只按数据解析：

- 使用 `JSON.parse`；
- 验证顶层必须为普通对象；
- 继续调用严格结果解析逻辑；
- 不执行其中的字符串；
- 不把字符串直接作为 HTML；
- 页面渲染继续使用 `textContent`。

### 8.3 公式和宏

系统不得执行 Excel 公式、宏或脚本。

建议在导入必要业务字段时拒绝公式单元格，只接受单元格的静态文本或数字值。该规则应在实现测试中覆盖。

导出时所有用户输入和模型文本都应作为普通文本单元格写入，不创建公式字段。

## 9. 时间更新规则

### 9.1 版本级时间

两个时间字段都属于评测版本：

```js
{
  firstExportedAt: null | ISODateString,
  updatedAt: ISODateString
}
```

同一版本下所有 Excel 行重复保存相同值。

### 9.2 第一次导出时间

- 新版本初始为 `null`；
- 第一次成功生成 Excel 时写入；
- 同一次导出使用同一个时间值；
- 后续导出不覆盖；
- 导出失败时不写入；
- 导入时保留 Excel 中的原值。

### 9.3 最后更新时间

以下操作更新所属版本的 `updatedAt`：

- 修改版本名称；
- 修改问题；
- 修改评分标准；
- 新增、修改或删除模型回答；
- 新增或删除记录；
- 完成评测；
- 重新评测并以最新状态覆盖旧状态。

以下操作不更新：

- 只切换当前显示版本；
- 只查看结果；
- 导入 Excel；
- 导出一个已经具有 `firstExportedAt` 的版本。

首次导出为版本写入 `firstExportedAt` 时，同时将该版本的 `updatedAt` 更新为本次导出时间。导出失败时两个字段都不因本次操作改变。

## 10. 删除与覆盖

### 10.1 删除评测版本

```text
用户点击删除
  ↓
弹出二次确认
  ├─ 取消：不改变状态
  └─ 确认：删除版本及其全部记录
             ↓
          重新渲染页面
             ↓
          后续导出不再包含该版本
```

已导出的旧 Excel 不会被修改。

### 10.2 重新评测覆盖

重新评测前不删除旧结果，以避免请求进行中页面暂时丢失已有内容。

当最新任务结束后：

- 成功：用新结果覆盖旧结果；
- 请求失败：清除旧成功结果，保存最新请求错误；
- 解析失败：清除旧成功结果，保存最新解析错误和原始返回。

覆盖完成后更新版本 `updatedAt`。

## 11. 错误处理

| 位置 | 处理方式 |
| --- | --- |
| SheetJS 未加载 | 禁用导入导出并显示依赖缺失 |
| 文件无法读取 | 保留当前数据，显示文件级错误 |
| 工作表结构错误 | 保留当前数据，显示缺失或冲突列 |
| 数据格式版本不支持 | 保留当前数据，提示支持的版本 |
| 单行字段错误 | 跳过该行，写入导入报告 |
| 结果 JSON 非法 | 跳过该行，写入具体 JSON 错误 |
| 摘要分数与 JSON 冲突 | 跳过该行，不猜测正确值 |
| 版本公共字段冲突 | 跳过冲突行，并报告字段与原因 |
| 没有合法行 | 不应清空当前数据；显示没有可导入记录 |
| Excel 生成失败 | 不写入首次导出时间，显示导出失败 |
| 单条评测失败 | 覆盖该记录为最新失败，不影响其他任务 |
| 用户手动终止评测 | 无旧成功结果的记录改为 `terminated`；已有成功结果的记录保留旧成功状态和结果 |

没有合法行时保留当前数据是已确认需求。
