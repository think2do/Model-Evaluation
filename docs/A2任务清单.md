# A2 版本任务清单

## 1. 使用说明

本清单根据以下文档拆分：

- [A2 版本需求说明](需求文档.md)
- [A2 技术选型与架构说明](A2技术选型与架构说明.md)

拆分原则：

- 每个任务只解决一个明确问题；
- 每个任务应能在一次对话内完成；
- 每个任务应能形成一个独立 commit；
- 每个任务都包含可检查的产出物和验收标准；
- 未完成依赖任务前，不提前实现后续功能；
- 功能实现与文档更新可以放在同一个对应任务中；
- 不把真实 API Key、用户评测数据或敏感 Excel 样例提交到仓库。

任务状态约定：

- `[ ]` 未开始
- `[~]` 进行中
- `[x]` 已完成
- `[!]` 被阻塞

# A2-00：确认剩余实现边界

## T01：确定版本公共字段冲突规则

**任务**

确定 Excel 中同一 `versionId` 的多行记录出现不同版本名称、问题、评分标准或时间字段时，系统如何处理。

**需要用户确认**

- 跳过冲突行；或
- 跳过整个评测版本；或
- 采用其他明确规则。

**产出物**

- 更新 `docs/需求文档.md`；
- 更新 `docs/A2技术选型与架构说明.md`。

**验收标准**

- 文档中只保留一种明确处理规则；
- 不再出现“第一行优先”或“最后一行优先”等隐式行为；
- 导入任务可以据此编写确定性测试。

**依赖**

无。

---

## T02：确定批量评测并发上限

**任务**

确定单条、单版本和多版本评测共用的最大并发请求数。

**需要用户确认**

- 最大并发数量；
- 超过上限的任务是否进入等待队列；
- 用户是否能看到“等待中”状态。

**产出物**

- 更新需求和架构文档中的并发规则。

**验收标准**

- 并发数量是明确整数；
- 超出上限时的行为明确；
- 不允许一次性无上限发送请求。

**依赖**

无。

---

## T03：确定评测中导出规则

**任务**

确定仍有记录处于“评测中”时是否允许导出。

**需要用户确认**

- 阻止导出；或
- 允许导出，并规定评测中记录在 Excel 中的状态。

**产出物**

- 更新需求和架构文档。

**验收标准**

- UI 和 Excel 状态映射都有唯一规则；
- 不把瞬时状态误写成成功或未评测。

**依赖**

无。

---

## T04：确定首次导出对更新时间的影响

**任务**

确定首次写入 `firstExportedAt` 时，是否同时更新版本的 `updatedAt`。

**产出物**

- 更新需求和架构文档中的时间规则。

**验收标准**

- 首次导出后的两个时间字段可以被唯一推导；
- 导出器测试不需要自行假设。

**依赖**

无。

---

## T05：确定零合法行的导入规则

**任务**

确定 Excel 整体结构有效、但所有数据行均无效时的处理方式。

**建议确认项**

- 保留网页原有数据；
- 显示“没有合法记录”；
- 列出全部错误行。

**产出物**

- 更新需求和架构文档。

**验收标准**

- 不存在是否清空当前网页数据的歧义；
- 导入器可以为零合法行建立明确测试。

**依赖**

无。

A2-T33 展示导入错误报告

如果某个任务在实现中明显超出一次对话或一个 commit，应继续拆分，不应把多个未完成方向压入同一提交。
