# 模型回答裁判器

一个仅在本地浏览器中使用的轻量模型评测网页。用户提供原始问题、二元评分标准和多份模型回答，网页调用 DeepSeek V4 Flash，展示逐项判定、证据、分数及排名。

当前项目只负责“裁判”，不负责生成题目、评分标准或候选回答。

## 核心功能

- 创建、切换、命名和删除多个评测版本；删除前二次确认。
- 输入原始问题、评分标准及多份“模型名称 + 模型回答”。
- 支持单条、当前版本未评测记录、当前版本全部记录和多版本评测。
- 每份回答独立调用 `deepseek-v4-flash`，批量最大并发数为 99，并可手动终止。
- 展示红线、原始分、最终分、得分率、逐项理由和直接证据。
- 对结构化成功的结果按最终分排序；同分并列。
- 保存未评测、成功、请求失败、解析失败和已终止状态。
- 重新评测使用最新结果覆盖；终止重新评测时保留旧成功结果。
- 将全部版本导出为单工作表 Excel，也可以用导入文件中的合法行全量替换网页数据。

## 运行要求

- 现代浏览器。
- 可访问 DeepSeek API 的网络环境。
- 一个可用的 DeepSeek API Key。

项目没有 npm 依赖、构建步骤、后端服务或数据库。Excel 功能使用仓库内固定版本的 SheetJS CE 0.20.3。

## 本地使用

以下命令均在项目根目录执行。

### 1. 配置 API Key

复制示例配置：

```bash
cp config.example.js config.js
```

编辑本地的 `config.js`：

```js
window.MODEL_EVALUATION_CONFIG = {
  deepSeekApiKey: "在本地填写你的 Key",
};
```

`config.js` 已被 `.gitignore` 排除，不应加入 Git。

### 2. 打开网页

直接双击根目录的 `index.html`，或使用任意静态文件服务器打开。项目不需要安装依赖、启动后端或运行构建命令。

### 3. 完成评测

1. 创建或选择一个评测版本。
2. 填写原始问题和评分标准。
3. 填写模型名称和回答；需要时添加更多回答。
4. 选择单条、当前版本或多版本评测入口。
5. 请求结束后查看排名，并通过模型标签切换逐项结果。
6. 需要保存或迁移全部数据时，使用 Excel 导出或导入。

## Excel 数据规则

- Excel 只包含一个名为“评测记录”的工作表。
- 导出包含全部版本和记录，并保存第一次导出时间与最后更新时间。
- 导入是“合法行全量替换”，不是追加、合并或去重。
- 文件中存在错误行时，合法行继续导入，错误行按实际行号列出。
- 文件整体无效或没有合法记录时，网页原数据保持不变。
- 不执行或信任 Excel 公式、宏和脚本；检测到公式或宏时拒绝导入。
- 评测运行期间不能导入或导出。

## 数据与安全边界

- API Key 由浏览器前端读取。任何能读取本地文件、页面源码或浏览器运行状态的人都可能获取它。
- 仅限个人本地使用；不要分享、上传或公开部署填写了 Key 的 `config.js`。
- 数据只保存在当前页面内存和用户主动导出的 Excel 中；刷新或关闭页面后，未导出的数据会消失。
- 不提供后端、登录、数据库、云端历史、题库或多人协作。
- 不生成问题、评分标准或候选模型回答。
- 不在网页中计算评测差值、趋势或统计看板。
- 不保留重新评测前的旧结果。
- 不自动修复非法或矛盾的裁判返回。

## 项目组成

- `index.html`：页面结构。
- `styles.css`：页面样式与响应式布局。
- `app.js`：页面控制、请求、严格解析、排名和结果渲染。
- `src/`：版本状态、并发评测、覆盖策略和 Excel 模块。
- `tests/`：使用 Node 内置测试运行器的自动化测试。
- `vendor/sheetjs/`：SheetJS CE 0.20.3、Apache-2.0 `LICENSE` 和 `NOTICE.md`。
- `config.example.js`：可提交的本地配置模板。
- `config.js`：本地真实配置，已被 Git 忽略。
- `process-recap/`：独立的项目过程复盘教学页面，不参与裁判器运行。
- `docs/`：当前项目文档和 A2 开发资料。

## 开源前必须处理

当前 Git 历史中的早期提交曾包含真实 API Key。仅修改当前文件不能从历史中删除该 Key。

在公开或推送仓库前必须：

1. 在 DeepSeek 控制台撤销或轮换旧 Key。
2. 清理包含旧 Key 的 Git 历史，或建立不含敏感历史的新仓库。
3. 确认 `config.js` 未被 Git 跟踪。
4. 对待发布文件和完整历史执行凭据扫描。
5. 确认远程仓库可见性。
6. 选择并添加项目级开源许可证。

在完成上述检查前，不应公开当前仓库或推送现有历史。
