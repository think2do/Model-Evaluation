# A2 版本需求说明：评测版本与 Excel 数据管理

## 1. 文档目的

本文档描述 Model Evaluation 项目 A2 版本的产品需求。

A2 版本将在现有单次模型回答评测能力之上，增加“评测版本管理”和“Excel 全量导入导出”能力，使用户能够在网页中同时维护多个评测版本，并通过 Excel 保存、恢复和继续处理全部评测数据。

本文档以已经确认的需求为主。仍需在详细格式设计阶段确认的事项会在对应位置明确标注，不在开发过程中自行推断。

---

## 2. 目标用户

A2 版本主要面向需要长期、重复测试模型表现的个人评测者。

目标用户通常需要：

- 在不同时间对模型回答进行评测；
- 保存问题、评分标准、模型回答和完整评测结果；
- 在同一个网页中管理多个评测版本；
- 提前通过 Excel 准备待评测数据；
- 将网页中的全部数据导出并长期保存；
- 将以前导出的数据重新导入网页继续处理；
- 在 Excel 中自行比较模型在不同时间的表现。

本版仍然是本地个人工具，不面向多人协作或云端数据管理。

---

## 3. 版本目标

A2 版本需要实现以下目标：

1. 用户可以在网页中创建和管理多个评测版本。
2. 每个评测版本独立包含完成评测所需的全部输入和结果。
3. 用户可以对未评测记录执行评测。
4. 用户可以重新评测已有结果，并以最新结果覆盖原结果。
5. 用户可以把网页中的全部数据导出为一个 Excel 文件。
6. 用户可以导入 Excel，并用导入内容完整替换网页中的现有数据。
7. Excel 同时承担数据备份、数据恢复和批量准备待评测内容的作用。
8. 导出数据需要同时保存第一次导出时间和最后更新时间。

---

## 4. 核心概念

### 4.1 评测版本

“评测版本”“大版本”和“批次”在本需求中表示同一个概念，统一称为“评测版本”。

评测版本由用户主动创建，而不是由每次点击评测按钮自动创建。

用户可以在同一个网页中同时创建、查看和管理多个评测版本。每个评测版本是一个相对独立的评测数据集合，至少包含：

- 版本标识；
- 版本名称；
- 评测问题；
- 评分标准；
- 一份或多份模型回答；
- 每份回答对应的模型名；
- 每份回答的评测状态；
- 每份回答的评测结果或错误信息；
- 第一次导出时间；
- 最后更新时间。

一个评测版本可以包含多份模型回答。不同回答可以分别处于未评测、评测成功、请求失败或解析失败等状态。

### 4.2 模型名

每份模型回答只设置一个“模型名”字段，用于标识该回答对应的模型。

A2 版本不再额外拆分“模型名称”和“模型版本”两个字段。如果用户需要记录具体版本，应直接写入模型名，例如：

- `GPT-5`
- `DeepSeek V4 Flash`
- `某模型 2026-07`

模型名只用于记录和展示，不参与裁判评分。

### 4.3 评测记录

评测版本中的每一份“模型名 + 模型回答 + 评测状态/结果”构成一条评测记录。

同一评测版本下的记录共享该版本的问题和评分标准，但各自保存：

- 记录标识；
- 模型名；
- 模型回答；
- 当前评测状态；
- 当前评测结果；
- 请求错误或解析错误；
- 原始裁判返回内容。

### 4.4 Excel 文件

Excel 文件表示网页当前全部评测数据的一份完整快照。

- 导出时，将网页中的所有评测版本和记录写入 Excel。
- 导入时，用 Excel 中的数据完整替换网页中的所有现有数据。
- 不执行追加、合并或去重。
- 再次导入同一个文件时，仍然直接覆盖网页当前数据。
- 删除网页中的评测版本后，下一次导出的 Excel 不再包含该版本。
- 已经保存在用户电脑中的旧 Excel 文件不会被网页自动修改。

## 5. 核心使用场景

### 5.1 创建多个评测版本

用户进入网页后，可以主动创建一个评测版本，填写版本名称、问题、评分标准，并添加一份或多份模型回答。

用户可以继续创建其他评测版本。多个版本同时保存在当前网页的数据状态中，彼此独立管理。

### 5.2 评测未生成结果的记录

用户可以对尚未生成评测结果的记录执行评测。

系统使用该版本的问题、评分标准，以及当前记录的模型名和模型回答，调用现有裁判流程生成结果。

这里的“生成”只表示生成评测结果，不生成新的问题、评分标准或候选模型回答。

### 5.3 重新评测已有记录

用户可以对已经存在结果的记录重新评测。

重新评测时：

- 使用当前保存的问题、评分标准、模型名和模型回答；
- 最新评测结果覆盖以前的结果；
- 无论最新结果成功、请求失败还是解析失败，都以最新状态覆盖旧状态；
- 不在系统中保留被覆盖的旧结果；
- 后续导出只包含覆盖后的最新结果。

### 5.4 导出全部数据

用户可以把网页当前保存的全部评测版本和记录导出为一个 Excel 文件。

导出文件：

- 只包含一个工作表；
- 每一条评测记录占一行；
- 使用不同列保存版本信息、输入信息、结果摘要和完整结构化数据；
- 可以再次被本系统导入；
- 反映导出时网页中的最新数据状态。

### 5.5 导入完整数据

用户可以选择一个符合 A2 格式要求的 Excel 文件并导入。

系统需要：

1. 读取并校验整个文件；
2. 确认文件可以被系统识别；
3. 校验成功后，清除网页中的现有数据；
4. 使用导入文件中的数据恢复全部评测版本和记录；
5. 恢复各条记录的当前评测状态；
6. 将没有评测结果的记录识别为“未评测”。

如果导入文件校验失败，系统不得清除或破坏网页中原有的数据。

### 5.6 通过 Excel 批量准备待评测内容

用户可以按照系统规定的 Excel 列结构，提前填写：

- 评测版本信息；
- 问题；
- 评分标准；
- 模型名；
- 模型回答。

这些行可以不填写评测结果。导入后，系统将其识别为未评测记录，用户可以在网页中对其执行评测。

### 5.7 删除评测版本

用户可以删除一个完整的评测版本。

删除后：

- 系统必须先显示二次确认，明确提示该版本下的全部记录将一起删除；
- 用户确认后才执行删除；
- 用户取消时不改变任何数据；
- 该版本及其包含的全部评测记录从网页中移除；
- 后续导出的 Excel 不再包含该版本；
- 以前已经导出的 Excel 文件不受影响。

## 6. 功能需求清单

### 6.1 评测版本管理

- [ ] 支持用户主动创建评测版本。
- [ ] 支持同时保存多个评测版本。
- [ ] 支持在不同评测版本之间切换。
- [ ] 每个评测版本具有稳定且唯一的版本标识。
- [ ] 每个评测版本可以填写版本名称。
- [ ] 每个评测版本独立保存问题和评分标准。
- [ ] 每个评测版本可以包含一份或多份模型回答。
- [ ] 支持删除完整评测版本。
- [ ] 删除评测版本前必须进行二次确认。
- [ ] 删除版本时同时删除该版本下的全部评测记录。
- [ ] 删除后的版本不进入后续导出文件。

### 6.2 评测记录管理

- [ ] 每条记录保存稳定且唯一的记录标识。
- [ ] 每条记录保存模型名。
- [ ] 每条记录保存完整模型回答。
- [ ] 每条记录保存当前评测状态。
- [ ] 支持对未评测记录执行评测。
- [ ] 支持对已有结果的记录重新评测。
- [ ] 重新评测结果覆盖原结果。
- [ ] 最新失败或解析错误同样覆盖旧成功结果。
- [ ] 不保留被覆盖的旧评测结果。
- [ ] 单条记录评测失败时，不影响同版本下其他记录的结果。
- [ ] 支持评测某一条记录。
- [ ] 支持评测当前版本下所有未评测记录。
- [ ] 支持重新评测当前版本下的全部记录。
- [ ] 支持一次选择并评测多个版本。

### 6.3 评测状态

每条记录至少需要支持以下状态：

- `未评测`
- `评测中`
- `评测成功`
- `请求失败`
- `解析失败`

导入时，系统根据文件内容恢复记录状态。没有评测结果且没有错误信息的有效记录应识别为“未评测”。

### 6.4 Excel 导出

- [ ] 将网页中的全部评测版本和记录导出为 `.xlsx` 文件。
- [ ] 一个导出文件只包含一个工作表。
- [ ] 每条评测记录占一行。
- [ ] 同一评测版本的公共信息可以在其每条记录中重复保存。
- [ ] 导出版本标识和版本名称。
- [ ] 导出问题和评分标准。
- [ ] 导出记录标识。
- [ ] 导出模型名和模型回答。
- [ ] 导出评测状态。
- [ ] 单独导出最终分数。
- [ ] 单独导出满分和得分率。
- [ ] 将完整评测结果以 JSON 文本保存在一个独立单元格中。
- [ ] 导出请求错误和解析错误。
- [ ] 导出原始裁判返回内容。
- [ ] 导出第一次导出时间。
- [ ] 导出最后更新时间。
- [ ] 导出文件能够被本系统重新导入。
- [ ] 已删除的数据不进入新导出的文件。
- [ ] 导出失败时显示明确错误，不伪装成导出成功。

### 6.5 Excel 导入

- [ ] 支持导入 `.xlsx` 文件。
- [ ] 从文件中的一个工作表读取全部数据。
- [ ] 导入前校验文件结构。
- [ ] 校验必填字段和数据类型。
- [ ] 校验完整评测结果 JSON 是否可以解析。
- [ ] 文件结构通过校验后，导入其中的合法行，并用这些数据替换网页全部数据。
- [ ] 跳过存在错误的行，不因单行错误拒绝其他合法行。
- [ ] 导入结束后列出所有被跳过的错误行及具体原因。
- [ ] 不追加到当前数据。
- [ ] 不合并当前数据和导入数据。
- [ ] 不对重复记录进行去重。
- [ ] 再次导入同一个文件时直接覆盖当前网页数据。
- [ ] 文件整体无法识别或无法执行导入时，保留网页原有数据。
- [ ] 恢复多个评测版本及其记录关系。
- [ ] 恢复已有结果、失败状态和解析错误。
- [ ] 将结果为空的有效记录恢复为未评测状态。
- [ ] 对无法识别的文件或字段显示明确错误。
- [ ] 不自动猜测、补齐或修复关键数据。

### 6.6 时间字段

系统需要为每个评测版本保存两个与导出有关的时间字段。版本下的所有评测记录共享同一组时间。

#### 第一次导出时间

记录该评测版本第一次被成功导出到 Excel 的时间。

第一次成功生成 Excel 时，系统在生成文件的同时，将本次导出时间写入此前尚无“第一次导出时间”的评测版本。

只有 Excel 成功生成后才能写入该时间；导出失败时不得把失败操作记录为第一次导出。

第一次成功导出后，该时间应作为历史信息保留，后续导出不得覆盖。

#### 最后更新时间

记录该评测版本最近一次发生有效更新的时间。版本内任意公共信息或评测记录发生有效变化时，都更新该版本的“最后更新时间”。

可能触发更新的操作包括：

- 修改版本名称；
- 修改问题或评分标准；
- 新增、修改或删除模型回答；
- 完成一次评测；
- 重新评测并覆盖结果；
- 新增或删除评测记录。

导入 Excel 只负责恢复数据，不算作数据更新。导入后应保留文件中原有的第一次导出时间和最后更新时间，不能因为导入操作而改写。

## 7. Excel 单工作表结构

### 7.1 基本规则

- 一个工作簿只使用一个工作表。
- 每一行表示一条模型回答评测记录。
- 同一评测版本下的多条记录使用相同的版本标识关联。
- 问题和评分标准在同版本的每一行中重复保存，保证每行数据可以独立理解。
- 动态数量的逐项评测结果不展开成大量动态列。
- 完整评测结果统一序列化为 JSON 文本，保存在一个单元格中。
- 最终分数等常用摘要字段仍单独设置列，方便用户直接在 Excel 中查看、筛选和比较。

### 7.2 建议列清单

以下列名是当前需求层面的建议，最终名称可在实现设计阶段确定：

| 列 | 内容 | 必填条件 |
| --- | --- | --- |
| 数据格式版本 | 标识 Excel 使用的 A2 数据格式版本 | 必填 |
| 评测版本 ID | 评测版本的唯一标识 | 必填 |
| 评测版本名称 | 用户填写的版本名称，允许为空 | 选填 |
| 问题 | 当前版本的评测问题 | 必填 |
| 评分标准 | 当前版本的评分标准 | 必填 |
| 记录 ID | 当前模型回答记录的唯一标识 | 必填 |
| 模型名 | 回答对应的模型 | 必填 |
| 模型回答 | 需要评测的完整回答 | 必填 |
| 评测状态 | 未评测、成功、请求失败或解析失败等 | 必填 |
| 最终分 | 当前结果的最终分数 | 成功结果必填 |
| 满分 | 当前结果的总分上限 | 成功结果必填 |
| 得分率 | 当前结果的整数百分比 | 成功结果必填 |
| 完整评测结果 JSON | 红线、评分项、理由、证据和校验信息 | 成功结果必填 |
| 错误类型 | 请求错误或解析错误 | 失败结果填写 |
| 错误信息 | 当前错误的可读说明 | 失败结果填写 |
| 原始裁判返回 | 裁判返回的原始文本 | 有返回内容时填写 |
| 第一次导出时间 | 当前版本第一次成功导出的时间，同版本各行一致 | 首次成功导出后填写 |
| 最后更新时间 | 当前版本最近一次有效更新的时间，同版本各行一致 | 必填 |

### 7.3 完整评测结果 JSON

完整评测结果 JSON 应尽可能保留现有裁判器已经解析和展示的全部结果信息，包括：

- 候选回答标识；
- 模型名；
- 红线是否触发；
- 红线说明；
- 适用红线规则；
- 所有评分项；
- 每个评分项的编号；
- 每个评分项的得分；
- 每个评分项的判定理由；
- 每个评分项的直接证据；
- 原始分；
- 满分；
- 最终分；
- 得分率；
- 分数校验信息。

最终分、满分和得分率虽然已经存在于 JSON 中，仍需分别导出为独立列。

## 8. 数据覆盖与安全规则

### 8.1 导入覆盖

导入属于“合法行全量替换”操作：

1. 系统先读取文件；
2. 先校验工作簿、工作表和必要列等整体结构；
3. 整体结构可以识别时，逐行校验数据；
4. 导入所有合法行，跳过存在错误的行；
5. 用本次导入的合法数据替换网页当前数据；
6. 导入完成后，向用户列出被跳过的行号及每行的具体错误；
7. 不进行追加、合并或去重；
8. 文件整体无法识别或无法执行导入时，保留网页原有数据。

同一评测版本的公共字段如果在不同行中互相冲突，应当如何处理，目前仍需在 Excel 格式设计阶段明确，不能静默选择其中一个值。

### 8.2 重新评测覆盖

重新评测完成后，无论结果为成功、请求失败还是解析失败，均使用最新状态覆盖旧状态。

系统不保存覆盖前的评测结果。如果用户需要保留旧结果，应在重新评测前自行导出 Excel。

### 8.3 删除规则

删除评测版本会删除该版本下的全部记录。

执行删除前必须弹出二次确认。只有用户明确确认后才能删除；用户取消时保持数据不变。

删除只影响网页当前数据以及之后生成的导出文件，不会修改以前已经导出的 Excel。

### 8.4 Excel 内容安全

- 不执行 Excel 中的宏、脚本或公式。
- 不把单元格内容作为 HTML 直接执行。
- 不根据格式错误的数据猜测关键字段。
- 不自动修正评测分数或评测结果 JSON。
- 导入错误必须明确显示，不能静默忽略。

## 9. 本版明确不做

A2 版本暂不包含以下能力：

- 不自动生成问题。
- 不自动生成评分标准。
- 不自动生成候选模型回答。
- 不保留重新评测前的旧结果。
- 不在网页中计算不同时间评测结果的差值。
- 不在网页中生成模型表现趋势。
- 不提供趋势图、对比图或统计看板。
- 不建立用户账号或登录系统。
- 不提供多人实时协作。
- 不建立云端数据库。
- 不提供云端历史记录。
- 不与已经导出的 Excel 文件实时同步。
- 不自动追加或合并导入数据。
- 不对重复导入进行去重。
- 不自动修复格式错误的 Excel。
- 不猜测缺失的问题、评分标准、模型名或模型回答。
- 不执行 Excel 中的公式、宏或脚本。
- 不改变现有裁判规则和严格解析原则。
- 不使用多个工作表保存关联数据。
- 暂不支持 CSV 或其他导入导出格式。
- 暂不提供定时评测或自动重新评测。
- 暂不提供跨文件的历史结果自动比较。

---

## 10. 已确认的实现规则

### 10.1 时间字段归属于评测版本

每个评测版本保存一组“第一次导出时间”和“最后更新时间”。该版本下的所有评测记录共享这组时间。

### 10.2 导入不更新时间

导入 Excel 不算作数据更新。系统应保留文件中原有的时间字段，直到用户实际修改版本内容或执行评测。

### 10.3 首次成功导出时写入时间

第一次成功生成 Excel 的同时，系统把本次时间写入尚无“第一次导出时间”的评测版本。导出失败时不写入。

### 10.4 版本名称允许为空

版本 ID 必须存在且唯一；版本名称由用户填写，但允许为空。

### 10.5 删除版本需要二次确认

删除评测版本前必须明确提示删除范围，并等待用户二次确认。

### 10.6 支持四种评测操作

系统同时支持：

1. 评测某一条记录；
2. 评测当前版本下所有未评测记录；
3. 重新评测当前版本下的全部记录；
4. 一次选择并评测多个版本。

### 10.7 导入合法行并报告错误行

文件整体结构可以识别时，系统导入所有合法行，跳过存在错误的行，并在导入完成后列出每个错误行及其具体原因。

## 11. A2 验收结果概述

A2 完成后，用户应当能够：

1. 在网页中主动创建多个评测版本；
2. 在每个版本中填写问题、评分标准和多份模型回答；
3. 对未评测记录执行评测；
4. 对已有记录重新评测，并以最新结果覆盖旧结果；
5. 删除不再需要的完整评测版本；
6. 将网页中的全部数据导出为单工作表 Excel；
7. 在 Excel 中直接查看最终分等摘要字段；
8. 通过 JSON 单元格完整保留动态评测结果；
9. 将 Excel 全量导入并恢复网页数据；
10. 导入预先准备但尚未评测的数据，并继续完成评测；
11. 通过第一次导出时间和最后更新时间识别数据时间；
12. 在 Excel 中自行比较不同文件或不同版本的模型表现。
